# Livewire to React Migration Plan

## Overview

Migrate the Cooperative Management System from Laravel Livewire 3 to a React SPA frontend. The backend (Laravel 12, Eloquent models, Spatie permissions, services) stays PHP — we replace the frontend layer entirely.

**Scale:** 36 Livewire components → React components, ~1 existing API endpoint → full REST API, 0 React code → React SPA.

---

## Decisions (Locked In)

| # | Decision | Choice |
|---|---|---|
| 1 | **React location** | Inside Laravel at `resources/react/` |
| 2 | **Auth strategy** | Laravel Sanctum SPA (cookie-based) |
| 3 | **Public pages** | Migrate everything to React (full SPA) |
| 4 | **State management** | React Context + React Query (no Zustand) |
| 5 | **Services decomposition** | Split into separate pages per service type |
| 6 | **Form library** | React Hook Form + Zod |
| 7 | **CSS** | Keep Tailwind v4 as-is |
| 8 | **UI components** | shadcn/ui |
| 9 | **Router** | React Router v7 |
| 10 | **Backend changes** | Existing backend logic (controllers, models, services, middleware) may be modified/refactored to better suit the React SPA — not just the API layer. Livewire-specific patterns can be removed or replaced. |

### Phase 9: Email System Overhaul

**Goal:** Fix email sending to use Laravel Jobs for async processing, add fallbacks for failed deliveries, and ensure reliable email delivery across all notification types.

**Current issues found:**
- `NotificationService` uses `Mail::queue()` (good) but has no error handling or fallback
- `SecurityOtpService` uses `Mail::send()` (synchronous) in some paths — blocks the request
- `PasswordResetController` uses `$mail->send()` (synchronous) — blocks the request
- No retry logic for failed emails
- No fallback if email delivery fails (user gets no feedback)
- Announcement notifications loop through users individually — no batching
- No `app/Jobs/` directory exists — no job classes defined
- Queue is set to `database` in `.env` — good foundation but unused

**Duration estimate:** 2-3 days

**Tasks:**

1. **Create email job classes** (`app/Jobs/`):
   - `SendEmailJob.php` — generic queued email job with retry logic (tries: 3, backoff: 60s)
   - `SendAnnouncementEmailJob.php` — batch announcement emails to multiple users
   - `SendOtpEmailJob.php` — OTP delivery with fallback to sync if queue is down
   - `SendSecurityAlertJob.php` — security alert emails (login, password change, etc.)

2. **Add error handling and fallbacks:**
   - Wrap all `Mail::to()->queue()` calls in try/catch
   - On queue failure: fall back to `Mail::to()->send()` (synchronous)
   - On send failure: log the error, create a failed activity log entry
   - For OTP emails: if async fails, try sync immediately (OTP is time-sensitive)
   - Add `failed()` method to each job for dead-letter handling

3. **Refactor `NotificationService`:**
   - Replace all direct `Mail::to()->queue()` with `SendEmailJob::dispatch()`
   - Add try/catch around each mail dispatch
   - Log failures via `AuditLogService` with tag `email.failed`
   - For announcement bulk emails: use `SendAnnouncementEmailJob` with user collection

4. **Refactor `SecurityOtpService`:**
   - Replace `Mail::to()->send()` with `SendOtpEmailJob::dispatch()->onQueue('emails')`
   - Add fallback: if job dispatch fails, try synchronous send
   - Add rate limiting check before sending

5. **Refactor `PasswordResetController`:**
   - Replace synchronous `$mail->send()` with job dispatch
   - Return success response immediately (don't wait for email)
   - Add error handling: if job fails, return user-friendly error

6. **Create email-specific queue connection:**
   - Add `emails` queue in `config/queue.php` (uses database driver)
   - Or use the default `database` queue with a dedicated queue name
   - This separates email sending from other queued work

7. **Update queue worker configuration:**
   - Ensure `php artisan queue:work` is running in production
   - Add `--queue=emails,default` to prioritize emails
   - Document queue worker setup in deployment notes

8. **Add email delivery logging:**
   - Log all email dispatches (success and failure) via `AuditLogService`
   - Tag: `email.sent`, `email.failed`, `email.retried`
   - Include: recipient, mailable class, failure reason

**Files to create:**
- `app/Jobs/SendEmailJob.php`
- `app/Jobs/SendAnnouncementEmailJob.php`
- `app/Jobs/SendOtpEmailJob.php`
- `app/Jobs/SendSecurityAlertJob.php`

**Files to modify:**
- `app/Services/NotificationService.php` — replace Mail::queue with job dispatch
- `app/Services/SecurityOtpService.php` — replace Mail::send with job dispatch

## Key Technical Decisions

### Authentication
- Use **Laravel Sanctum** with cookie-based SPA auth
- React app on same domain (or proxied) to share cookies
- Axios interceptor adds `X-XSRF-TOKEN` header from cookie
- Login via `POST /api/login` returns user + permissions

### State Management
- **React Context** for global state: `AuthContext` (user, permissions, login/logout), `SidebarContext` (expand/collapse), `ThemeContext` (dark/light)
- **React Query** for server state: all API data fetching, caching, optimistic updates, refetch intervals
- Local component state (`useState`) for forms, modals, wizard steps

### Form Handling
- **React Hook Form** with **Zod** schemas for validation
- Zod schemas can be shared/derived from Laravel FormRequest rules
- Field-level validation on blur (matching current Livewire behavior)

### Routing
- **React Router v7** with nested layouts
- Role-based route guards via `ProtectedRoute` wrapper component
- URL-based section routing (replaces Livewire's `#[Url]` attribute)

### File Uploads
- Direct `FormData` uploads to API endpoints (no Livewire `WithFileUploads`)
- `react-dropzone` or shadcn Upload component for UI
- Progress tracking via Axios `onUploadProgress`

### Charts
- **react-chartjs-2** (wraps Chart.js) for reports and overview dashboards
- Same Chart.js dependency, just consumed differently

### PDF Export
- Keep **DomPDF** on Laravel side
- React sends request → Laravel generates PDF → returns download or blob
- Could also add client-side PDF generation for simple reports later

### Real-time Updates
- Initially use **polling** (React Query `refetchInterval`) for notifications, pending counts
- Could upgrade to WebSockets (Laravel Reverb + Pusher) later if needed

### Auth Flow Verification

The auth flow should work as follows:
1. Page loads → React mounts → AuthProvider mounts
2. AuthProvider calls `GET /api/user` (with Sanctum cookie)
3. If authenticated → `user` is set → React Router shows dashboard
4. If not authenticated → `user` is null → React Router shows login page
5. User submits login form → `POST /api/login` → session created → `GET /api/user` → user set → redirect to dashboard
6. Logout → `POST /api/logout` → session destroyed → `user` set to null → redirect to login

**Critical fix needed:** `AuthController::formatUser()` must use `$user->name` instead of `$user->first_name . ' ' . $user->last_name`
